## [BLOCKING] Initial workspace startup bypasses project trust decision

**File:** `apps/omega-desktop/electron/main.js:646-650`
**Rule:** Security / Authentication and authorization; project-local resources must not activate before trust

**Issue:** Startup accepts a workspace from command-line, environment, or deep-link input, adds it to the registry, and acquires a worker using `projectTrust.isTrusted(cwd)` without returning the `trust_required` state used by normal workspace switching. An undecided project containing trust-requiring resources can therefore activate through startup without the trust UI decision.

**Current code (lines 646-650):**
```js
646 | const requested = startupRequest.workspace ? realRoot(resolve(startupRequest.workspace)) : realRoot(rootOf());
647 | const cwd = workspaceRegistry.has(requested) ? workspaceRegistry.resolveAuthorized(requested) : workspaceRegistry.add(requested);
648 | activeCwd = cwd;
649 | const slot = await acquireSlot({ sessionId: startupRequest.sessionId, cwd, projectTrusted: projectTrust.isTrusted(cwd) });
650 | activeSlot = slot;
```

**Fix:** Inspect trust before worker activation; use `projectTrusted: false` for undecided projects and surface `trust_required`, matching workspace switching. Never treat startup path provenance as trust.

## [BLOCKING] Failed worker startup can orphan the child process

**File:** `apps/omega-desktop/electron/worker-pool.js:233-250`
**Rule:** Resource management / process lifecycle

**Issue:** When `host.start()` rejects, the pool removes the slot but never calls `host.kill()`. A child forked before initialization failure can remain alive and retain resources while becoming unreachable from the pool.

**Current code (lines 233-250):**
```js
233 | try {
234 |   await host.start(initPayload);
235 |   host.activating = false;
236 |   slots.set(pendingId, slot);
237 |   return slot;
238 | } catch (error) {
239 |   host.activating = false;
240 |   slots.delete(pendingId);
241 |   throw error;
242 | }
```

**Fix:** Best-effort `await host.kill()` in the catch path before rethrowing, and cover it with a startup-failure regression test.

## [BLOCKING] Worker kill leaves initialization promise pending

**File:** `apps/omega-desktop/electron/worker-host.js:205-237`
**Rule:** Error handling / resource management

**Issue:** `kill()` changes state and kills the child but does not clear or reject `_initResolve`/`_initReject` or `_initTimer`. `_handleDeath()` returns for `stopping`, so `start()` can remain pending until the 60-second timeout during shutdown.

**Fix:** Clear the timer, reject pending initialization with a disposal error, null callbacks, then kill the child idempotently.

---

## [BLOCKING] Close teardown stops before guaranteed worker termination

**File:** `apps/omega-desktop/electron/close-lifecycle.js:22-41`
**Rule:** Error handling / resource management

**Issue:** A rejection from `abort()` or `flush()` exits `runWorkerTeardown()` before `dispose()` and `kill()`. A partial worker failure can therefore leave the worker alive during application close.

**Fix:** Execute each step independently, collect errors for diagnostics, and always attempt `dispose()` and `kill()`.

## [BLOCKING] Unbounded paged file reads can freeze the Electron main process

**File:** `apps/omega-desktop/electron/workspace-service.js:84-93`
**Rule:** Algorithmic complexity / input validation / denial-of-service prevention

**Issue:** `readFilePage` reads and splits the entire file before applying the requested page slice. A renderer request against a multi-gigabyte text file allocates the whole file and an unbounded line array despite the returned page limit.

**Fix:** Reject files over a configured byte threshold before reading, or implement streaming/byte-range paging with a per-request byte budget.

## [BLOCKING] File upload has a parent-directory symlink time-of-check/time-of-use gap

**File:** `apps/omega-desktop/electron/file-transfer-service.js:56-64`
**Rule:** Security / path containment and symlink safety

**Issue:** The upload path is validated before creating/writing the destination, but a parent directory can be replaced by a symlink between validation and write. The subsequent write can escape the authorized workspace.

**Fix:** Open/create the destination using a descriptor or re-canonicalize the parent immediately before write, rejecting symlinked components and using exclusive creation where required.

## [BLOCKING] Untracked diff loading is unbounded

**File:** `apps/omega-desktop/electron/diff-service.js:335-343`
**Rule:** Performance and resource management

**Issue:** `untrackedHunks` loads untracked files without a size cap into memory. A large untracked file can block the main process and exhaust memory.

**Fix:** Apply a maximum file size and truncate/skip oversized files before reading, or stream bounded hunks.

---

## [BLOCKING] State-reader performs unbounded synchronous filesystem and JSON work on the Electron main process

**File:** `apps/omega-desktop/electron/state-reader.js:101-105,238-352,441-489`
**Rule:** Performance and resource management

**Issue:** State aggregation synchronously reads and splits complete append-only files with no byte, line, task, or output limits. A large or malformed journal can block the main thread and allocate multiple intermediate arrays during one IPC request.

**Fix:** Use bounded streaming reads, enforce resource limits, process incrementally, cache results, or move aggregation to a worker. Return truncation metadata at limits.

---

## [BLOCKING] Download output stream errors are unhandled

**File:** `apps/omega-desktop/electron/updater-service.js:120-145`
**Rule:** Error handling / resource management

**Issue:** The writable output stream has no `error` listener. Disk-full, permission, and filesystem errors can become unhandled stream errors and terminate the process; cleanup and single-settlement are not coordinated.

**Fix:** Attach output error handling that destroys the response/request, removes the temporary file, and rejects once; use `pipeline()` where possible.

## [IMPORTANT] Same-checksum downloads are incorrectly deduplicated across destinations

**File:** `apps/omega-desktop/electron/updater-service.js:111-118`
**Rule:** Correctness / shared mutable state

**Issue:** `activeDownloads` is keyed only by checksum, so concurrent requests for the same asset to different destination directories return the first request's path to the second caller.

**Fix:** Include the normalized destination directory in the deduplication key, or copy the completed artifact into each requested destination.

## [IMPORTANT] Agent text deltas bypass the renderer payload cap

**File:** `apps/omega-desktop/electron/agent-bridge.js:237-239`
**Rule:** Input validation / resource limits

**Issue:** `text_delta` forwards the SDK delta directly while adjacent event types are capped by `MAX_PAYLOAD_CHARS`. A pathological event can allocate and forward an oversized IPC payload.

**Fix:** Cap text deltas to the same bounded payload policy and add a multi-megabyte regression test.

## [IMPORTANT] Tool-call transcript formats are inconsistent

**Issue:** IDs are sliced to 128 characters instead of rejected when overlong, changing caller input and allowing collisions or stale-resource mismatches.

## [IMPORTANT] Credential vault writes are not concurrency-safe

**File:** `apps/omega-desktop/electron/credential-store.js:46-51`
**Rule:** Resource management / data integrity

**Issue:** All writes use one predictable process-wide temporary filename. Concurrent updates can overwrite or rename each other's temp file, lose credentials, or fail with `ENOENT`; replacement semantics also require explicit Windows handling.

**Fix:** Serialize mutations, use unique exclusive temp files, flush before replacement, and use a platform-safe replacement strategy with restrictive permissions.

## [IMPORTANT] Settings temp files do not request restrictive permissions

**File:** `apps/omega-desktop/electron/desktop-settings.js:76-81`
**Rule:** Data protection / secure persistence

**Issue:** The atomic temp write relies on the process umask and inherited Windows ACLs. Provider metadata can contain sensitive endpoint/account information.

**Fix:** Create temp files with mode `0o600`, apply user-only ACLs on Windows, and minimize persisted provider metadata.

## [IMPORTANT] Session-summary traversal can inspect an unbounded directory tree

**File:** `apps/omega-desktop/electron/session-reader.js:30-49`
**Rule:** Performance and resource management

**Issue:** The traversal caps collected JSONL files but not queued directories, depth, entries, symlink directories, or elapsed time. A directory-heavy session root can make synchronous traversal expensive before the file cap is reached.

**Fix:** Bound directories, depth, entries, and elapsed time; skip symlink directories and prefer asynchronous/indexed traversal.
